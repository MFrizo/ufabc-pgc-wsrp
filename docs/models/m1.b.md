# M1.b — Native Gurobi Multi-Objective Formulation with Lifted MTZ (MO-DOMDVRPTW-SD)

- **Builder:** `build_model_m1_b` in `src/models/model_1_b.py`
- **Role:** native Gurobi multi-objective implementation of [M1.a](m1.a.md) using Gurobi's `setObjectiveN` solver API
- **Instance settings:** same as [M1](m1.md) and [M1.a](m1.a.md) (`num_brokers = 3`, `fixed_ratio = 1.0`, `service_time_variation = 30`, `speed_profile = NORMAL_SPEED`, `start_at_homes = True`, `lunch_break = (180, 360, 60)`, `max_day_length = 720`; default seed 8).

In [M1](m1.md) and [M1.a](m1.a.md), the multi-objective nature of the problem is scalarized into a single objective using artificial weights:
- A very large fleet weight $W_{frota}$ to enforce minimizing the number of active brokers as the highest priority;
- Operational weights $W_{time} = 1.0$, $W_{atraso} = 10.0$, and $W_{extra} = 100.0$;
- An infinitesimal tie-break distance weight $W_{dist} = 1 / (U + 1)$ to settle ties between plans with equal time, delay, and overtime.

**M1.b** replaces scalarization with **Gurobi's native multi-objective optimization engine (`setObjectiveN`)**, eliminating the need for artificial Big-$W$ numbers and infinitesimal scaling factors.

## Objective Hierarchy in M1.b

Gurobi solves multi-objective problems lexicographically using priority levels:

| Priority | Objective Component | Mathematical Term | Weight | Role |
| :---: | :--- | :--- | :---: | :--- |
| **2** | Fleet size (`fleet`) | $\sum_{k \in K} y_k$ | $1.0$ | Primary: minimize the number of brokers who work |
| **1** | Travel time (`travel_time`) | $\sum_{(i,j,k) \in \mathcal{A}} t^k_{ij} x_{ijk}$ | $1.0$ | Operational cost: driving time |
| **1** | Delay (`delay`) | $\sum_{i \in C_h} \text{delay}_i$ | $10.0$ | Operational cost: penalty per minute of booked visit delay |
| **1** | Overtime (`overtime`) | $\sum_{k \in K} \text{overtime}_k$ | $100.0$ | Operational cost: penalty per minute of overtime |
| **0** | Total distance (`distance`) | $\sum_{(i,j,k) \in \mathcal{A}} c^k_{ij} x_{ijk}$ | $1.0$ | Tie-breaker: settle plans with identical fleet and operational costs |

Because Distance is placed at **Priority 0**, it strictly functions as a tie-breaker without distorting the operational trade-offs, and without requiring the $1/(U+1)$ divisor.

## Polyhedron Formulation

M1.b inherits the exact tightened polyhedron of [M1.a](m1.a.md):
- Iterative time-window domain reduction $[a_i, b_i]$ via network reachability;
- Arc-specific tightened Big-M parameters $M^k_{ij} = \max(0, b_i + s_i + t^k_{ij} - a_j)$;
- Desrochers and Laporte (1991) lifted MTZ bounds and 2-cycle elimination.

## Solution Algorithm: Gurobi Multi-Objective vs. M1.a Scalarization

Although M1.b and M1.a share the exact same lifted MTZ polyhedron and evaluate the same 5 problem components, their underlying solution algorithms and solver mechanisms are fundamentally different.

### 1. Gurobi Multi-Objective Algorithm (M1.b)

Gurobi solves multi-objective models using **Sequential Lexicographic (Hierarchical) Optimization with Objective Bounding**, combined with **Blended (Weighted-Sum) Optimization** within tiers that share the same priority:

1. **Tier Grouping and Blending:**
   Objectives sharing the same priority level are aggregated into a single weighted sub-objective:
   $$\min \sum_{j \in \text{tier } k} w_j f_j(x)$$
   In M1.b, travel time ($w=1$), delay ($w=10$), and overtime ($w=100$) share Priority 1 and are blended proportionally.

2. **Sequential Multi-Stage Solves:**
   Gurobi solves a sequence of $m$ separate optimization sub-problems from highest to lowest priority:
   - **Stage 1 (Priority 2 — Fleet):**
     $$\min \text{fleet}(x) = \sum_{k \in K} y_k \quad \text{s.t.} \quad x \in \mathcal{X}$$
     Let the optimal fleet size be $z_1^*$.
   - **Objective Bounding Constraint (Objective Cut):**
     Before proceeding to Priority 1, Gurobi injects an implicit bounding constraint:
     $$\text{fleet}(x) \le z_1^* + \text{abstol}_1 + \text{reltol}_1 \cdot |z_1^*|$$
     With default tolerances ($\text{abstol} = \text{reltol} = 0$), the fleet size is frozen to its proven minimum $z_1^*$.
   - **Stage 2 (Priority 1 — Operational Costs):**
     $$\min \Big(\sum_{(i,j,k) \in \mathcal{A}} t^k_{ij} x_{ijk} + 10 \sum_{i \in C_h} \text{delay}_i + 100 \sum_{k \in K} \text{overtime}_k\Big)$$
     $$\text{s.t.} \quad x \in \mathcal{X}, \quad \text{fleet}(x) \le z_1^*$$
     Let this optimal operational cost be $z_2^*$. Gurobi adds the cut: $\text{ops}(x) \le z_2^*$.
   - **Stage 3 (Priority 0 — Distance Tie-Breaker):**
     $$\min \text{distance}(x) = \sum_{(i,j,k) \in \mathcal{A}} c^k_{ij} x_{ijk} \quad \text{s.t.} \quad x \in \mathcal{X}, \quad \text{fleet}(x) \le z_1^*, \quad \text{ops}(x) \le z_2^*$$

3. **Solver Warm-Starting Across Stages:**
   Rather than solving each stage in isolation, Gurobi preserves the simplex basis, incumbent solutions, and valid cutting planes between stages, significantly speeding up subsequent stages.

---

### 2. M1.a Solution Algorithm (A Priori Scalarization)

In contrast, [M1.a](m1.a.md) solves the problem in a **single pass (one branch-and-cut tree)** by scalarizing all 5 terms into a single objective:

$$\min W_{\text{frota}} \cdot \text{fleet} + W_{\text{time}} \cdot \text{travel} + W_{\text{atraso}} \cdot \text{delay} + W_{\text{extra}} \cdot \text{overtime} + W_{\text{dist}} \cdot \text{distance}$$

To simulate lexicographic priorities within a single objective function:
- **Fleet minimization** requires an artificially huge penalty weight ($W_{\text{frota}} = 10{,}000$) to guarantee that saving one broker dominates any possible combination of driving time, delay, or overtime.
- **Distance** requires an infinitesimal tie-break weight ($W_{\text{dist}} = \frac{1}{U + 1} \approx 10^{-4} \text{ to } 10^{-6}$) to ensure distance never interferes with operational trade-offs measured in minutes.

---

### 3. Comparison and Key Differences

| Feature | M1.a (Scalarized Sum) | M1.b (Gurobi Multi-Objective) |
| :--- | :--- | :--- |
| **Optimization Method** | Single-pass Branch-and-Cut over 1 scalar objective | Multi-pass Sequential Lexicographic Optimization with Objective Bounding |
| **Number of Sub-Solves** | Exactly 1 solve | 3 sequential sub-problems (one per priority level) |
| **Weight Semantics** | Global trade-off coefficients across *all* components | Local weights *only within* the same priority tier; ignored across tiers |
| **Numerical Conditioning** | **High dynamic range**: coefficients span $10^4$ down to $10^{-6}$ (ratio $10^{10}$) | **Normalized**: every stage uses natural unit scales ($1.0, 10.0, 100.0$) |
| **Tie-Breaking** | Requires artificial divisor $1 / (U + 1)$ | True lexicographical tie-break via Priority 0 |
| **Degradation Flexibility** | Rigid; changing trade-offs requires recalibrating all weights | Native via `abstol` and `reltol` per priority tier |

---

### 4. Practical & Computational Implications

- **Numerical Stability & Tolerance Masking:**
  In M1.a, the tiny weight $W_{\text{dist}} \approx 10^{-6}$ creates a dynamic range of $10^{10}$ in objective coefficients. On larger instances, distance variations can fall below the solver's internal optimality tolerances (`MIPGap` or `OptimalityTol`), risking suboptimal or arbitrary distance selections. In M1.b, distance is optimized at Priority 0 with full numeric scale ($w = 1.0$).
- **Search Space Pruning:**
  In M1.b, Stage 1 proves the minimum fleet size $K^*$ very rapidly. The bounding cut $\sum y_k \le K^*$ immediately eliminates all sub-trees using more than $K^*$ brokers from the Stage 2 search space.
- **Solution Equivalence:**
  On well-calibrated instances where no operational cost sum exceeds the gap of one broker, both formulations converge to the **exact same optimal routing sequence** (verified via `Route Sequence Match: IDENTICAL` in `--compare-objectives`), but M1.b does so with superior numerical conditioning and without artificial Big-W scaling.
