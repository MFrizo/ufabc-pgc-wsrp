# M1.b — Native Gurobi Multi-Objective Formulation with Lifted MTZ (MO-DOMDVRPTW-SD)

- **Builder:** `build_model_m1_b` in `src/models/model_1_b.py`
- **Role:** native Gurobi multi-objective implementation of [M1.a](m1.a.md) using Gurobi's `setObjectiveN` solver API
- **Instance settings:** same as [M1](m1.md) and [M1.a](m1.a.md) (`num_brokers = 3`, `fixed_ratio = 1.0`, `service_time_variation = 30`, `speed_profile = NORMAL_SPEED`, `start_at_homes = True`, `lunch_break = (180, 360, 60)`, `max_day_length = 720`; default seed 8).

In [M1](m1.md) and [M1.a](m1.a.md), the multi-objective nature of the problem is scalarized into a single objective using artificial weights:
- A very large fleet weight $W_{frota}$ to enforce minimizing the number of active brokers as the highest priority;
- Operational weights $W_{time} = 1.0$, $W_{atraso} = 10.0$, and $W_{extra} = 100.0$;
- An infinitesimal tie-break distance weight $W_{dist} = 1 / (U + 1)$ to settle ties between plans with equal time, delay, and overtime.

**M1.b** replaces scalarization with **Gurobi's native multi-objective optimization engine (`setObjectiveN`)**, eliminating the need for artificial Big-$W$ numbers and infinitesimal scaling factors.

## Objective Hierarchy in M1.b

Gurobi solves multi-objective problems lexicographically using priority levels:

| Priority | Objective Component | Mathematical Term | Weight | Role |
| :---: | :--- | :--- | :---: | :--- |
| **2** | Fleet size (`fleet`) | $\sum_{k \in K} y_k$ | $1.0$ | Primary: minimize the number of brokers who work |
| **1** | Travel time (`travel_time`) | $\sum_{(i,j,k) \in \mathcal{A}} t^k_{ij} x_{ijk}$ | $1.0$ | Operational cost: driving time |
| **1** | Delay (`delay`) | $\sum_{i \in C_h} \text{delay}_i$ | $10.0$ | Operational cost: penalty per minute of booked visit delay |
| **1** | Overtime (`overtime`) | $\sum_{k \in K} \text{overtime}_k$ | $100.0$ | Operational cost: penalty per minute of overtime |
| **0** | Total distance (`distance`) | $\sum_{(i,j,k) \in \mathcal{A}} c^k_{ij} x_{ijk}$ | $1.0$ | Tie-breaker: settle plans with identical fleet and operational costs |

Because Distance is placed at **Priority 0**, it strictly functions as a tie-breaker without distorting the operational trade-offs, and without requiring the $1/(U+1)$ divisor.

## Polyhedron Formulation

M1.b inherits the exact tightened polyhedron of [M1.a](m1.a.md):
- Iterative time-window domain reduction $[a_i, b_i]$ via network reachability;
- Arc-specific tightened Big-M parameters $M^k_{ij} = \max(0, b_i + s_i + t^k_{ij} - a_j)$;
- Desrochers and Laporte (1991) lifted MTZ bounds and 2-cycle elimination.

## Execution and Notebook Usage

### CLI
```bash
python main.py --model m1.b
```

### In a Jupyter Notebook
```python
from src.core.listings import load_instance
from src.models import build_model_m1_b
from src.solvers.engine import solve_model
from src.utils.parsers import print_results

# Load instance
data = load_instance("real", "m1.b", num_properties=5, random_seed=8)

# Build and solve M1.b
model = build_model_m1_b(data)
solved_model, metrics = solve_model(model)

# Print results with multi-objective breakdown
print_results(solved_model, metrics=metrics)
```
